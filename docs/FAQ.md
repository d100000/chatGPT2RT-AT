# ChatGPT Token 提取 FAQ：RT、AT、转换与部署

以下回答针对 bob ai工具当前实现。项目是非官方的已有授权账号工具，不是 OpenAI 官方产品；“支持某种功能”不等于保证认证服务始终接受该登录方式。

## 如何获取 ChatGPT 的 RT 和 AT？

在自己控制的设备上启动 bob ai工具，导入已有授权账号，完成认证服务要求的验证。成功时会同时取得 AT、RT 和 ID Token，并自动保存结果。网页支持批量，CLI / Python API 每次处理一个账号。操作步骤见 [Token 提取指南](TOKEN-GUIDE.md)，安装命令见 [README](../README.md#快速开始)。

## “GPT 提取 Token”是在创建 API Key 吗？

不是。该项目导出账号登录后的认证 Token，不会为账号创建 OpenAI API Key，也不会为账号开通 API 权限、额度或付费套餐。

## RT、AT 和 ID Token 能相互替代吗？

不能按名称互换。导出字段分别为 `refresh_token`、`access_token`、`id_token`，承担不同认证用途。接收文件的工具必须支持相应的账号类型和字段；把 RT 粘贴成 AT，或把 ID Token 改名为 API Key，不会使其成为另一种凭据。见 [Token 术语表](../README.md#token-types)。

## AT 到期意味着 RT 也失效了吗？

不能这样判断。本项目中的 `expires_at` 表示 AT 到期时间，不是 RT 的生命周期。RT 是否可用取决于签发服务，凭据可能被撤销。项目不保证 RT 的有效期，也没有 RT 自动续期功能。

## 可以只复制已有结果而不重新登录吗？

可以。成功账号旁的“查看 RT”会读取已保存结果；下载 JSON、RT 文本或 ZIP 也只读取结果，不重新登录。纯 CPA / Sub2API 转换则整理已有认证文件，不兑换 Token、不刷新凭据，也不进行认证有效性测试。

## 缺少 RT 但拿到了 AT，算成功吗？

不算。本项目要求 AT、RT 和 ID Token 均为非空值，才将该账号标记成功。不要把登录中的部分数据解释为已完成、可长期使用的认证结果。

## 能否跳过 2FA、邮箱验证或手机号验证？

不能。2FA 密钥用于生成 Authenticator 动态码，不替代服务端额外验证。网页在要求邮箱验证码时提供对应账号的输入表单；项目不包含自动邮箱取码、手机号验证或自动注册流程。

## 网页批量提取的上限是多少？

每批最多 1000 个账号、2 MiB 文本；同时处理账号数默认为 2，可选 1～3。等待验证码的账号仍占用名额。账号和批次还受服务端频率配额约束，单批上限不等于允许连续无限提交，详见 [安全策略](../SECURITY.md)。

## Token、密码和 2FA 密钥到底存在哪里？

纯转换导入的认证内容仅保留在当前页面内存，不上传、不写入浏览器存储。Token 获取会让凭据经运行 Python 的设备处理，并把成功结果保存为该设备上的明文文件；服务器部署时，文件在服务器上。程序不将输入密码和 2FA 密钥持久保存到结果文件；自行创建的 `account.json` 仍包含其原有凭据。

声明确认时间、IP 检测缓存和匿名防刷 Cookie 是另行记录的站点状态，不包含输入的账号 Token。详情见 [使用声明与隐私](../README.md#使用声明与隐私)。

## 关闭浏览器或重启后，Token 文件会删除吗？

不会自动删除。输出目录中的成功文件继续保留，七天声明周期也不负责清理文件。刷新页面可以恢复当前批次；重启可恢复最近三个已保存的已结束批次，但不能续跑重启前的活动登录。

## CPA 转 Sub2API 后，所有字段都能原样转回来吗？

不能。转换只映射已知字段，未知扩展字段、代理和调度配置不保证完整往返保留。反向转换只处理可映射到 CPA 的 OAuth 账号，不支持的账号会显示跳过原因。源模块、支持平台和字段说明见 [转换与字段映射](../README.md#cpa--sub2api-格式转换)。

## IP 检测的分数可以保证登录成功吗？

不能。IPOK 分数描述本次已返回的 IP 风险证据，不是登录成功率、账号安全证明或地区解锁保证。检测对象是浏览器出口，提取页的代理只影响 Python 登录请求，两者可能不同。缺少当前有效评分时页面不会构造一个分数。

## 为什么账号输入有内容，条数仍为 0，开始按钮不可用？

这通常需要先排查页面初始化，而不是账号密码。若 Console 报 `Cannot use import statement outside a module`，检查是否有旧模板把含 `import` 的新 `app.js` 当普通脚本加载。代码、安装包、模板和静态资源应使用同一版本，更新后重启实际应用服务，再刷新浏览器。详见 [维护说明](MAINTAINERS.md#module-loading)。其他错误应以实际 Console、Network 和页面提示为依据。

## 看到 HTTP 429 应该怎么做？

按服务器 `Retry-After` 等待。本站针对 IP、匿名设备、Session、账号和全局设置配额，页面会显示冷却时间并保留未提交成功的输入，不自动重提密码或验证码。上游认证服务和 IPOK 也可能有独立限额；应先确认是哪一个请求返回 429，避免把不同来源的配额混为一谈。

## 可以直接开放为多人公共 Token 提取服务吗？

当前代码没有公网用户登录、用户数据隔离或共享任务后端，不能把增加限流等同于完成多人服务的隔离。默认服务只允许本机访问。远程自用可保持 loopback 并使用 SSH 隧道；公开部署需要另行完成身份验证、私有存储和可信入口配置，见 [部署边界](../SECURITY.md#服务器使用边界)。

## 代码公开就代表整个项目采用 MIT 许可证吗？

不是。主项目当前没有声明完整的项目许可证。CPA 转换相关第三方模块的 MIT 通知已保留，但不代表整个项目适用同一许可；相关出处见 [第三方通知](../THIRD_PARTY_NOTICES.md)。

## 如何提交问题，让维护者容易复现？

到 [GitHub Issues](https://github.com/d100000/chatGPT2RT-AT/issues) 提供提交版本、运行方式、操作步骤和脱敏错误。说明故障发生在页面加载、接口提交、账号验证、结果生成还是转换阶段。不要附密码、2FA 密钥、Token、未脱敏网络响应或含凭据截图。
