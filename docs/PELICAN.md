# GPT 能力评测 · SVG 动画题库

入口：工具导航的 **GPT 能力评测**，路径 `/pelican`。首页也有入口，各工具导航会显示当前评测后台任务。现有 Token 获取、格式转换、IP 检测保留原有接口和数据处理方式。

题库包含 100 道原创 SVG 动画题，以及保留的“鹈鹕骑自行车”静态基线。用于观察指令执行、空间结构、动画时序与运动关系。**不能代表总体智力、换算人类 IQ 或证明接口上游模型身份。四维 20 分是本项目视觉任务评分，不是官方基准分。**

## 操作流程

1. 输入 Base URL 或完整 Responses / Chat Completions 地址、API key，选择协议。URL 中的代理路径保留；不能在 URL 中夹带凭据或查询参数。读取模型目录，或手动填写模型 ID（每行一个）。默认仅选 `gpt-6.1-sol`，实际可用性由接口决定。
2. **随机题目默认开启**，从 100 道动画题中抽取。单次测试抽一道；批量每次抽题后让所有所选模型回答同一道题，单轮请求数为抽题次数 × 模型数。同一任务抽完 100 道前不重复，持续或定时任务接着抽，用完后重新打乱。关闭开关后可手选动画题或静态基线，固定批量请求数为题目 × 模型 × 重复次数。简单模式只使用一道题、一个模型、一次请求。页面启动前显示请求数量。
3. **只测试一次**执行单题单模型一次；**执行计划**执行一轮，或按定时设置执行。定时首轮立即开始，完成后等待间隔，最多轮数 0 表示不限。**开始持续循环测试**完成并保存一轮后立即执行下一轮，忽略定时间隔和轮数上限。
4. 在后台任务区域查看进度或点击停止。任务由服务端执行，页面刷新、切换、关闭不停止任务。停止会取消本地等待和在途请求，保留部分输出，不启动下一轮。取消不能保证上游停止计算或计费。
5. 在历史中查看 SVG、技术检查、原始回答、SSE / JSON 证据、返回模型、耗时、首字、Token、HTTP 状态、结束原因和完整生成参数。选择多个样本可并排比较。缺失用量与 JSON 回退首字显示“未知”，真实 0 保留。
6. 图片实际渲染后可填写人工评分，每维必须提供 0–5 整数、具体理由和问题位置。动画题在评分窗口播放原始 SVG，评审者须确认已观看至少一个完整周期。两名不同评审者使用不同代号分别提交；匿名评审随机打乱样本并隐藏模型、性能、已有评分，动画仍可播放。代号与观看确认由用户声明，不能证明现实身份独立或自动验证观察过程。修改评分保留修订记录。
7. 静态基线支持可选 AI 看图评审：单独启用并配置具备图像理解能力的评审接口，点击“发送图片并请求 AI 评审”才会发起请求。只发送浏览器实际渲染的 PNG 与评分表，不发送 SVG 源码或被测模型名称，不将意见用于修图。动画题不提供单帧 AI 评分，因为静态截图不能验证运动和时序。失败不新增分数，保留 AI 尝试记录。
8. 查看分析报告，下载完整 JSON、公式注入防护 CSV、可离线打开的图文 HTML 或原始 SVG。导出遵循当前历史筛选，包含失败与取消，不筛选“最好结果”。

## 题面与规则

100 道动画题覆盖不同场景、运动关系和时序约束，题面要求单个自包含 SVG，以 SMIL 动画表达运动，不使用 JavaScript 或外部资源。题目为本项目原创，不冒充第三方官方基准。每题具有稳定 ID、题面与规则版本和独立评分要点。

保留题目 `pelican-bicycle`，版本 `1.0`，来源：[simonw/pelican-bicycle](https://github.com/simonw/pelican-bicycle)。关闭随机开关并选择该题时，发送内容逐字为：

```text
Generate an SVG of a pelican riding a bicycle
```

原题仅一条用户消息；无系统提示、工具、示例、上下文、反馈修图或自动重试。提取第一个完整顶层 SVG 预览，记录完整 SVG 数量，保留整个原始回答及响应证据（密钥脱敏除外）；不修复 XML 或图形结构。

题库注册入口是 `rt_extractor/eval_catalog.py` 中的 `QUESTIONS`。每题包含 id、version、title、category、abilityTags、prompt、outputFormat、source、scoringRubric、rubricVersion、enabled；动画题另外标记 `animation: true`。创建任务时冻结题池快照，每条样本保存实际抽到的题面和规则，历史不会随题库更新变化。API 参数 `random_questions` 默认为 `true`，关闭须显式传 `false`；开启时忽略手选 `questions`。旧历史缺少该字段时仍按固定题目解释。任务列表只返回题库数量等摘要，完整题库快照保留在导出中。

动画题使用与题面匹配的四维评分表，覆盖主体、运动、协同关系和画面可读性；每维 0–5，总分 20。静态基线保留鹈鹕辨识、自行车结构、骑乘关系、构图与可读性四维原规则。具体规则与统一分档在评分窗口显示。总分差 ≥ 4 或任一维差 ≥ 2 时提示复核；复核保留原评分与均分，不静默覆盖。修改原评分后原复核归档，需要重新复核。

## 保存与运行边界

- 评测独立保存到 `~/.local/share/bob-ai-tools/pelican/pelican.sqlite3`，可用 `GPT_EVAL_DATA_DIR` 指定目录。数据库文件权限为 `0600`，新目录权限为 `0700`；未设置自动清理，不触碰旧 Token 或账号数据。备份应包含整个评测目录。
- 独立、签名的 HttpOnly 历史 Cookie 用于区分浏览器，签名密钥保存在评测库中，服务重启后仍可读取历史。Cookie 有效期一年；清除 Cookie 或换浏览器后不能自动找回原历史。保留 JSON 导出作为可移植副本；当前不提供导入、网页历史删除或跨设备账号同步。
- API key 仅在输入框与活动服务端请求内存中使用，启动成功后清空输入框；不写浏览器存储、SQLite、日志或导出。原始输出中的已知密钥、Bearer 和常见 `sk-` 密钥形式被脱敏，图像内容不做其他修正。
- 默认 `high`、16000 最大输出 Token、600 秒总超时、流式、Responses `store=false`。支持取消 reasoning 参数。Chat 使用 `max_completion_tokens`；不静默降级参数、协议或模型，不跟随重定向，不重试。
- 每个浏览器同时一个评测任务，全服务最多四个活动评测任务；**每个计划固定串行（并发 1）**。不同浏览器任务可能同时运行。比较条件中保留并发参数。本机单应用进程运行，不支持多个进程共享调度；不要对同一历史目录同时启动多个服务实例。
- 正常停止保留取消时收到的部分输出。崩溃重启将未结束的记录标为中断，保留最后一次已落盘的部分内容，不自动恢复或重发。首段可见输出立即落盘，其后最多每秒一次；进程硬崩溃可能丢失最后一个检查点之后的片段。
- 历史写入失败立即停止计划，并在当前服务内存保留未保存样本，页面可下载该样本。磁盘故障无法保证落盘，服务退出会丢失这部分内存。
- 单个响应正文最多 16 MiB，超出明确记为失败并保留已经接收的部分内容，不重试。单轮最多 3000 请求、最多 30 模型、每模型每题最多 100 次。持续模式没有轮数上限，会持续消耗接口额度与磁盘空间。

## SVG 与浏览器渲染

技术检查分开记录：请求成功结束、存在完整 SVG、XML 结构有效、安全检查、浏览器实际渲染。采用元素与属性检查及 CSS 解析，拒绝脚本、事件、外部资源、DTD、实体、`@import`、`foreignObject` 等。允许不访问外部资源的 CSS `@keyframes`、`@media` 与 SMIL 图形动画；动画只能修改允许的几何、颜色和显示属性，不能修改链接、事件、样式或其他动画的配置。未知元素、CSS 函数和 at-rule 仍按保守规则拒绝；保留原始输出，绝不通过删内容伪装成功。

安全检查版本独立记录为 `technical.checker_version`。服务启动时按当前版本重新检查旧样本，保留 `technical_audit` 中的旧结论；不重新生成、不改变原始回答、SVG、生成参数或评分证据。

预览仅使用 `<img>` 的 SVG data URL，不把模型内容注入 HTML。通过安全检查且浏览器成功解码后，用 canvas 保存最大边 1200 像素的 PNG（不改变 SVG 源码），附源 SVG 和 PNG 的 SHA-256、尺寸、时间及 `first-loaded-frame-v1` 捕获策略，后续查看不会覆盖证据。PNG 只证明单帧成功渲染，不证明动画正确。动画题的人工评分、匿名评审和离线报告播放原始安全 SVG；评分另记录 SVG 哈希与观看周期确认。静态基线的人工、匿名和 AI 评审仍使用同一张已保存 PNG，即便模型额外生成了动画，也只按原静态题规则评价该画面。

**关闭所有页面时只继续生成与技术检查；浏览器渲染及评分等待用户打开相应样本。** 渲染率的分母是已实际尝试渲染的样本，同时展示渲染覆盖率和全部样本成功渲染比例，不把未查看样本假称成功。有效 SVG 不等于画对了题目。失败、取消、无效或没有渲染证据的样本不允许视觉评分。

## 报告口径

按题目版本、规则版本、请求模型及完整生成参数分组；不把不同条件混为一组。统计样本、成功、失败、取消、有效 SVG、浏览器渲染、评分覆盖率、各维均分、总分均值与范围、重复样本总体标准差、评审方式和数量、分歧与复核。每个样本先计算其评审均分，再计算样本间均分，避免多评审样本权重更大。

视觉分只基于已评分样本，明确分母；失败率和评分覆盖率同步显示。耗时与 Token 用量单独列出，未知不当 0。不将小样本的微小差异称为稳定排名或统计显著结果。HTML 包含全部匹配样本的图片、评分证据、失败明细以及批次完整快照。

## 本地验证

不需要真实 API key，不调用收费接口：

```bash
python -m unittest tests.test_pelican -v
node --test tests/test_eval_ui.mjs
python -m unittest discover -s tests -q
node --test tests/*.mjs
```

后端测试会自动启动临时本地 HTTP 模拟接口，覆盖 Responses / Chat、SSE / JSON、首字、用量、SVG 安全、错误、截断、超时、循环与停止、写入失败、重启、评分、匿名视图、导出及跨浏览器隔离。

浏览器端到端测试额外需要 Playwright（可指定外部模块路径，无须成为生产依赖）：

```bash
PELICAN_PYTHON=/path/to/python \
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs \
PELICAN_CHROME='/path/to/chrome' \
node tests/browser/pelican.mjs
```

此测试启动独立临时历史库和模拟接口，验证真实 SVG 解码与 PNG、两份人工评分、盲评、AI 看图请求、JSON / CSV / HTML / SVG 文件下载、跨页循环、取消、刷新、桌面与手机布局。截图和下载留在命令输出的临时目录中，不注入正式历史。

手动调试模拟提供商可运行 `python -m tests.pelican_mock --port 8878`，在评测页填写它打印的本地 URL、任意测试密钥，以及 `mock-good` / `mock-error` / `mock-slow` 等模型。仅用于开发验证，生产界面不包含模拟样本。
